# 2026 MaixCAM Pro 双模式拼图视觉

本项目将以下两个仓库整合为一个可由 MaixVision 直接打开的 MaixPy 项目：

- `superiwan/2026_new`：设备入口、绿色 A4 检测、420x594 透视校正、固定碎片查表识别和 UART 实现基础；
- `superiwan/2026_vision_v1`：题 2(1) 纯白随机多边形的边长配对、邻接图恢复、位姿图优化和矩形质量门限。

坐标平面固定为 420x594 px，对应 A4 纸 210x297 mm，即 `0.5 mm/px`。两个 Solver 都返回 `List[PieceAction]`；Solver 成功并通过质量门限后，设备入口通过 UART0 发送动作。

## 目录

```text

core/serial_protocol.py       STM32 红绿点 UART 文本协议

solvers/task2_config.py       白片上游求解参数
solvers/task3_poker.py        题2(2)扑克识别 + 复用纯白拓扑求解
tests/test_merged_project.py  PC 合成回归
```

## 设备运行

1. 在 MaixVision 中打开整个项目目录，运行 `main.py`。
2. 使用与实拍 `3.jpg`、`4.jpg` 同类的浅绿色 A4，保证四条边完整可见。定位同时检查绿色通道优势、饱和度、面积、凸四边形和 A4 长宽比；黑色底板不再兼容。
3. 点击屏幕顶部 `[TASK2 WHITE]` 或 `[TASK2 POKER]`。设备屏幕只显示 ASCII 英文，避免固件字体缺失导致乱码；中文诊断仍输出到 MaixVision 终端。
4. 两个模式均依次使用 `[FIND A4]`、`[DETECT]`、`[SOLVE]`、`[RESET]`。每块散片和目标拼图轮廓上都有白色小点，标记该轮廓的固定起始顶点，用于肉眼判断旋转方向。
5. A4 锁定后，实时画面显示矩形四角 `Q0`～`Q3`、中心点 `C` 及其原始相机像素坐标，并显示透视分界线；检测后右侧显示矫正 A4 预览、碎片编号和目标轮廓。每块碎片使用一对连续编号：零散位置为 `P0/P2/P4...`，对应的拼好位置为 `P1/P3/P5...`。相机或 A4 移动后重新按 `[FIND A4]`。

模式二和模式三使用共享的 `80 s` 求解 deadline。所有标准拓扑、连续切割和动态缩放路径
共享同一个 deadline，不会给每条搜索路径分别重新计时；这些路径也都有明确的拓扑候选
上限，不再执行完整拓扑或矩形覆盖穷举。解算过程中会持续保留综合评分最好的完整拼图候选。
正常结果必须通过填充率、重叠率、矩形尺寸、模式比例和 A4 摆放门限；到达 `80 s` 时则
立即停止搜索并采用此前最好的完整候选，即使该候选没有通过这些门限。普通质量失败不会提前
触发低质量兜底，避免在 deadline 前发送错误矩形。

## Solver 契约

每个 Solver 实现：

```python
actions, diagnostics = solver.solve(rectified_rgb)
```

其中每个 `PieceAction` 包含：

```text
piece_id
pick_x, pick_y, pick_angle
place_x, place_y, place_angle
confidence
```

坐标单位为毫米，原点为矫正后 A4 左上角，X 向右、Y 向下；角度沿图像坐标正方向计算并归一化至 `[-180, 180)`。
模式二和模式三在矩形拓扑求解通过后，会将各块目标位置向外分开，保证碎片边界之间约有 `5 mm` 安全间隙。右侧 `TARGET` 预览与 UART 的 `place_x/place_y` 使用同一组带间隙目标坐标。
拼好图的最上边缘固定放在 A4 中轴线下方 `25 mm`，X 方向居中；如果带间隙的目标图形无法完整放入下半区，则返回错误，不会压到中轴线或 A4 底边。
现场碎片的目标矩形不再假定固定 `10:6` 比例；候选评分在赛题允许范围内不偏好特定长宽比，最终按长边 `90～120 mm`、短边 `50～90 mm` 验收，并为透视和轮廓误差各保留 `5 mm` 容差。
标准拓扑和连续切割都未找到有效解时，模式二会进入有限的动态缩放 fallback。它根据候选
接缝两侧的长度误差，为每块碎片解算 `0.95～1.05` 范围内的独立等比缩放，缩放中心固定为
碎片自身中心，轮廓形状、边数和边长比例不变；随后只重跑有候选上限的标准/连续切割拓扑。
缩放仅用于补偿透视、阴影和分割造成的轮廓尺寸误差，最终动作矩阵仍只有旋转和平移，拾取
坐标仍使用原始检测轮廓。候选必须继续通过填充率、重叠率、尺寸和 A4 可放置硬门限。

## UART

使用 MaixCAM Pro `UART0`，`115200` 波特率：A17 为 RX，A16 为 TX，两块板必须共地并使用 3.3 V 电平。

先在屏幕顶部选择纯白或扑克模式。STM32 通过 USART6 向 MaixCAM 发送
`<ok>\r\n`，两个模式都使用同一握手流程：
`<ok>` 只触发当前已选模式的识别或下一块数据发送，不包含模式号，也不会切换模式；
两个模式始终只能通过屏幕顶部按键手动切换。
本轮第一次收到 `<ok>` 后，程序用当前帧自动执行 A4 识别、碎片识别和求解；
Solver 成功后，每块碎片生成一组相机原始像素坐标和旋转角度：绿色点为碎片初始位置，
红色点为拼好后的目标位置，角度为绿色初始姿态到红色目标姿态的顺时针旋转量。
三个字段各占一行，并通过同一次 `UART.write()` 写出：

```text
gre:(pick_px,pick_py)\n
deg:(clockwise_degree)\n
red:(place_px,place_py)\n
```

前缀固定为小写 `gre:` / `deg:` / `red:`，括号内不含空格；坐标用 `int()` 转成整数，
角度四舍五入为 `0..359` 的整数（例如逆时针 90 度发送为顺时针 `deg:(270)`）。
每行以 `\n` 结尾。毫米动作点会经锁定的 A4 逆透视矩阵反投影到相机像素；
只有绿点和红点同时位于标定有效范围 `x=27..495`、`y=96..453` 时才发送，
不发送 `(0,0)` 或 `(-1,-1)` 占位。串口为 `115200 8N1`，摄像头 TX 接
STM32 USART6 的 PC7（RX），并共地。

一次 `<ok>` 最多发送一块碎片。首个 `<ok>` 在自动识别成功后发送第 1 块；主控
完成搬运后再次发送 `<ok>`，程序才发送下一块。全部碎片发送完后，程序按主循环节拍
持续发送 `<over>\r\n`；收到下一个 `<ok>` 时停止发送 `<over>`，重新抓取当前帧并开启
新一轮 A4/碎片识别。切换模式或重置也会立即停止发送。

只有 A4、碎片、Solver 和该轮所有坐标都有效时才会发送；任一步失败均不发送
占位值，等待 STM32 约 1 秒后的 `<ok>` 重试。屏幕 `WAIT ACK N` 表示已经准备好
N 块，`UART SENT i/N` 表示本次 ACK 已发送第 i 块。

为避免识别完成后的界面拖慢相机预览，右侧矫正图只在 A4、检测或求解结果变化时重建。`DETECT` 后直接按 `SOLVE` 会复用同一份矫正图和碎片轮廓，避免重复分割并保证求解对象与屏幕确认结果一致。

## 扑克算法边界

纯白与扑克模式使用完全相同的拼图算法。扑克模式仅保留独立的碎片分割：采用上游
`lvreng/puzzle-vision-simulator` 的黑纸中位亮度加相对偏移阈值，并保留当前项目的
面积、边界和多 epsilon 多边形质量筛选；真实切边允许保留到 8 个顶点，避免凸包把
凹切边抹掉。只有纯白轮廓不超过 5 个顶点且与扑克轮廓面积一致时才复用纯白轮廓。
分割完成后，扑克碎片仍进入模式二 `Task2WhiteSolver.solve_detected()` 的四条默认有界搜索路径。
扑克模式额外对候选切边两侧的颜色和向内梯度做轻量连续性评分：达到几何门限的候选不会立即
采用第一个结果，而是在最多 12 个 finalist 中选择牌面接缝更连续、且填充率损失不超过
`1.5%` 的候选。该评分只改变扑克候选排序，不改变拓扑生成、动态缩放、动作坐标或 UART。
进入 finalist 的完整候选会同步登记到有界超时候选池；因此设备在 `80 s` 内未完成全部搜索时，
仍按同一 `1.5%` 填充率窗口和接缝连续性规则选择矩形，而不会退回仅按几何代价记录的旧候选。

扑克牌短边/长边仍要求 `5:7`，相对误差允许 `10%`。比例在碎片紧密拼合的矩形上验收，不能
在为机械放置人为加入 `10 mm` 间距后再次验收，否则合法牌面会被间距误判。只有真正达到
`80 s` deadline 时，才允许用未通过比例或其他安全门限的最佳完整矩形兜底。

扑克物理轮廓若出现由 1～3 段短弦连接两条长直边的可信圆角，程序会检查两侧直边近似垂直、
圆拟合残差、圆弧切深和半径范围，再延长直边恢复供模式二使用的虚拟尖角。四块测评输入中若且
仅若存在一对同形碎片，模式二完成后只构造 `original` 和 `swapped` 两种分配。严格长方形/正方形
门限未识别出同形对时，仍按面积、轮廓、顶点数和宽高类型选择最相似的一对，不能跳过比较。
两种分配使用无间距牌面上的内部接缝连续性，以及两个相似牌角是否位于相对外角共同评分；角标模型
只作辅助证据，证据不足也必须选出得分更好的分配。部署侧可通过 `Task3PokerSolver(corner_evidence_detector=provider,
require_disambiguation=True)` 注入角标检测器；provider 只需实现 `detect(rectified_rgb)`，返回含
`bbox_xyxy`（或 `center`）、`confidence`，以及可选 `direction` 的记录，扑克算法不依赖具体
YOLO 运行时。非四块历史回归仍保持原有模式二委托行为。

角标仍用于唯一同形长方形/正方形碎片对的 `original` / `swapped` 二选一和 UI 诊断。真实碎片
轮廓不满足该严格同形条件时，不依赖角标强行决定布局，而由上述有界接缝连续性排序选择共享
拓扑结果。角标模型缺失、漏检或证据不足不会阻止扑克几何搜索。

设备入口启动时从
`/root/models/poker_corner_yolo11n_640_int8_v2.mud` 加载单类
`corner_mark` YOLO11n 模型。模型和同目录 `.cvimodel` 缺失或加载失败时，纯白和扑克模式仍可使用；
角标模型只作为可选消歧证据，不会阻止扑克几何搜索或 UART 动作生成。可通过环境变量
`POKER_CORNER_MODEL` 指定另一份 `.mud`。

当前部署模型为绿色 A4 微调 v3，使用官方 `yolo11n.pt` 的黑底域权重继续训练，固定
`imgsz=640`。独立合成 test 的 Precision/Recall/mAP50/mAP50-95 为
`0.9800/0.9343/0.9599/0.8094`；四张绿色来源图的同源诊断为 `8/8`，不等同于独立
真实场景准确率。
CV181x INT8 产物位于本机忽略目录
`output/poker_corner_conversion_640_v2/poker_corner_yolo11n_640_int8_v2.*`，并已上传到设备
`/root/models`；MaixPy 已验证可加载为单类 RGB YOLO11、输入 `640x640`。四张绿色矫正图
设备回放检测数为 `2/2/2/2`，置信度 `0.8047–0.8594`。这仍是固定图片回放，不是实时
相机准确率或 UART 电气验收。训练数据、指标和限制详见
`docs/poker-yolo-real-finetune-v3.md` 与 `docs/poker-corner-dataset-research.md`。
运行时使用 `dual_buff=False`，因为每轮只推理一张锁定后的矫正图，不能接受双缓冲带来的
首帧延迟或上一帧结果。

目标布局不再按共同中心统一放大，而是只对间距不足的碎片对做最小平移；这样仍保持
约 `5 mm` 边界间距，同时避免两片方向接近时把其他碎片推开几十毫米。

`codex/fast-topology` 是速度优先的实验分支：拓扑求解使用保守粗筛并在首个填充率达到 97% 的候选处停止。当前主分支也不再执行无上限完整 fallback，但会在快速拓扑失败后增加有界动态缩放搜索。

回放耗时，不等同于未叠加 UI 的原始相机帧、纯白题实拍或 UART 电气链路验收。

设备端可使用有界启动回归，不需要点击按钮，也不会持续运行：

```text
python3 main.py --device-smoke=120
```

该模式执行真实相机、Display、Touch、OpenCV/Maix 图像桥接和双模式绘制路径，
达到指定帧数后正常退出。`image.cv2image(..., copy=False)` 会借用 NumPy 内存，
因此代码必须保留 `canvas` 引用直到 `display.show()` 完成，不能直接传入临时数组。

2026-07-30 在 MaixCAM Pro 上用同一组合成 A4/三碎片输入进行有界阶段回放（不含真实相机采集）后，FIND A4 为约 0.29–0.31 s，纯白/扑克 DETECT 分别约 0.21/0.32 s。识别结果稳定后的 UI 渲染约 11–19 ms/帧，`cv2image` 约 0–1 ms，`display.show` 约 2–4 ms。速度优先拓扑下，同一三碎片回放的纯白/扑克 SOLVE 分别约 0.34/0.43 s。真实场景准确率、camera.read 和持续显示 FPS 仍必须在当次机位与光照下复测，不能由合成回放数字代替。
