# 扑克牌同形碎片 YOLO + 圆弧消歧执行方案书

## 1. 项目目标

在保留现有模式二几何求解、动作生成、UI 和 UART 协议的前提下，为扑克牌模式增加一个有限的视觉消歧层。

测评场景的已知条件：

- 一共最多 4 块碎片；
- 恰好有 2 块形状相同，形状为长方形或正方形；
- 这 2 块上的扑克牌角标不会被截断；
- 另外 2 块不规则碎片可由现有模式二算法确定拼接关系；
- 最终只需要比较同形两块的 `original` 与 `swapped` 两种分配；
- 证据不足时必须返回 `AMBIGUOUS`，不能向 STM32 发送未经确认的动作。

本项目不让 YOLO 直接预测拼图结果。YOLO 只负责检测角标视觉证据，圆弧算法只负责识别扑克牌原始外角，现有模式二继续负责几何拼接。

## 2. 推荐总体架构

```text
相机图像
  -> 绿色 A4 定位与 420x594 透视校正
  -> 现有扑克碎片分割
  -> 保留每块碎片的实测物理轮廓
  -> 圆弧检测与虚拟直角恢复
  -> 模式二求解几何布局
  -> 找到唯一同形碎片对
  -> 构造 original / swapped 两个候选
  -> YOLO 角标检测并关联到碎片
  -> 圆角、角标位置、角标方向和牌面参考联合评分
  -> 唯一通过：生成现有 PieceAction
  -> 并列或证据不足：AMBIGUOUS，不发送 UART
```

推荐按“硬约束优先、模型分数最后使用”的方式决策：

1. 两个候选必须继续满足现有填充率、重叠率、尺寸和 A4 可放置门限。
2. 完整牌面必须恰好恢复 4 个可信物理圆角。
3. 检出的角标必须落在碎片内部，并能关联到某个物理圆角。
4. 候选变换后，角标必须落在完整扑克牌允许的角标区域并朝向牌面内部。
5. 只有一个候选满足全部硬约束且分数超过差值门限时才能输出。

## 3. 启动前必须确认的决策

AI 在开始下载数据、训练、转换或部署前，必须记录以下答案。没有答案时只能完成资料调研和小规模原型，不能开始正式训练。

| 决策 | 推荐默认值 | 影响 |
| --- | --- | --- |
| 扑克牌范围 | 固定一张牌 | 最容易形成可靠参考图和角标模型 |
| 若非固定牌 | 明确牌面清单，不默认覆盖 52 张 | 决定类别数和采集工作量 |
| YOLO 任务 | 先做单类 `corner_mark` 检测 | 只定位角标，类别简单、部署稳定 |
| 方向判断 | 检测后增加轻量方向判断 | 普通 bbox 本身不能可靠解决 180 度方向 |
| 训练起点 | 官方 `yolo11n.pt` | 优先保证 CV181x 部署体积和速度 |
| 训练尺寸 | `imgsz=640` | 小角标优先保证精度，设备测速后再决定是否降分辨率 |
| 数据集策略 | 公开数据预训练/补充 + 当前设备实拍为主 | 防止公开整牌数据与现场碎片域不一致 |
| 数据保护 | 原始数据只读，清洗后另建版本目录 | 禁止覆盖用户原图和旧标注 |
| 设备策略 | 先 PC 验证，再 INT8，再真机 | 不把 PyTorch 指标当成设备指标 |
| 运行时 | 模型启动时加载，每轮矫正图只推理一次 | 避免重复加载和重复推理 |

### 固定牌与随机牌的分支

固定一张牌时，推荐使用：

- YOLO 单类角标检测；
- 固定完整牌面参考图；
- 仅在 `original` 和 `swapped` 两个候选之间做局部模板或特征验证。

随机多张牌时，AI 必须先确定是：

- 小范围已知牌面：按牌面建立参考图和有限类别；
- 完整牌组：拆成点数、花色、方向等子任务，不建议直接训练 52 类小角标后立即部署。

如果两个角标在内容和 180 度旋转后完全对称，YOLO 无法创造不存在的信息。此时必须使用已知完整牌面纹理，或允许结果为 `AMBIGUOUS`。

## 4. 阶段化执行计划

### 阶段 A：项目与环境审计

AI 要完成：

- 阅读根目录 README、项目级 `AGENTS.md` 和现有扑克历史文档；
- 记录当前 Git 分支和未提交改动，不覆盖现有工作区；
- 检查 GPU、CUDA、Python、Docker、Ultralytics、ONNX 和 `tpu-mlir` 环境；
- 检查 MaixCAM Pro 型号、MaixPy 版本、摄像头分辨率和模型目录；
- 建立独立的实验目录和产物清单。

产物：

- `environment-report.md`；
- 工具版本和可用性记录；
- 数据、训练、转换和部署目录约定；
- 明确哪些已有文件不得覆盖。

停止条件：GPU、Docker 或转换环境缺失不是算法失败。AI 应报告缺失项和替代路径，不能伪造训练或设备结果。

### 阶段 B：公开数据集与许可调研

当前候选数据源、许可证和官方部署资料已整理在
[`poker-corner-dataset-research.md`](poker-corner-dataset-research.md)。后续 AI 必须先复核
该文档的来源是否仍可访问、许可是否变化，再执行下载。

AI 要搜索以下类别的数据，而不是只搜索“playing cards dataset”：

- 扑克牌整牌检测数据；
- 扑克牌角标、点数和花色识别数据；
- 小目标、旋转目标或遮挡目标数据；
- 可合法使用的完整扑克牌牌面素材；
- 适合做负样本的纸片、印刷图案和绿色背景图像。

每个候选数据源必须记录：

- 官方页面或原始仓库 URL；
- 发布者；
- 许可证；
- 图像数量、类别、标注格式和图像分辨率；
- 是否包含旋转、透视、遮挡、模糊和小角标；
- 是否允许修改、再发布和竞赛使用；
- 是否真正适合“碎片上的角标”，而不是只有完整扑克牌框；
- 建议用途：预训练、负样本、合成素材或不采用。

禁止事项：

- 不得把没有明确许可证的搜索引擎图片批量加入训练集；
- 不得默认 Roboflow、Kaggle 或 GitHub 项目中的图片都可重新分发；
- 不得把公开测试集混入训练集；
- 不得仅凭数据集名称判断其适用性。
- 不得把训练数据的许可与 Ultralytics 软件许可混为一谈；交付或闭源分发前必须核对
  AGPL-3.0/Enterprise 许可路径。

产物：

- `docs/poker-corner-dataset-research.md`；
- 数据源采用/拒绝表；
- 下载和校验命令草案；
- 许可证文件保存要求。

### 阶段 C：真实场景采集方案

公开数据只能作为补充。正式模型必须包含当前 MaixCAM Pro、当前镜头、绿色 A4 和比赛照明条件下的真实图片。

建议采集矩阵：

| 变量 | 建议覆盖 |
| --- | --- |
| 碎片位置 | A4 上半区不同位置，中心和四周都覆盖 |
| 碎片旋转 | `0..360` 度连续覆盖，不只四个直角方向 |
| 光照 | 正常、偏暗、偏亮、局部阴影、轻微反光 |
| 距离与焦点 | 比赛固定高度为主，加入少量可接受偏差 |
| 角标大小 | 靠近和远离画面中心，覆盖透视后的最小像素尺寸 |
| 背景干扰 | 花色、人物图案、切边、白色高亮、手或夹具短暂出现 |
| 同形布局 | 原位与交换各自均衡，避免模型学习位置偏差 |

数量建议：

- 先采集 300 至 500 张 pilot，跑通标注、训练、导出和真机推理链路；
- 根据 pilot 的真实失败簇扩充到 1500 至 3000 张去重后的真实帧；
- 至少 5 次独立采集 session；
- 每个 session 重新摆放相机或灯光，避免相邻视频帧泄漏；
- 保留没有完整角标的负样本；
- 保留角标靠近碎片边缘但未被截断的困难样本。

划分方式必须按采集 session 或场景分组：

- `train`: 70%；
- `val`: 15%；
- `test`: 15%；
- 同一段视频的相邻帧不得跨 split。

### 阶段 D：合成数据生成

为降低真实采集压力，可从具有合法使用权的完整牌面生成碎片图，但合成数据不能替代真实测试集。

合成器需要：

- 使用比赛允许的长方形、正方形和不规则切割；
- 保证指定角标完整；
- 在绿色 A4 背景上随机平移和旋转；
- 模拟透视、曝光、白平衡、阴影、模糊、噪声和 JPEG 压缩；
- 输出 YOLO 标注以及碎片、圆角和角标之间的关联真值；
- 能生成 `original` 与 `swapped` 的下游判断真值。

合成数据建议不超过训练集的 50%，并在消融实验中比较：

- 仅真实数据；
- 真实 + 合成；
- 公开数据预训练 + 真实微调。

### 阶段 E：标注规范与数据验证

推荐第一版检测类别：

```text
0 corner_mark
```

标注对象应覆盖完整的“点数/字母 + 花色”角标区域，不只框单个数字，也不要框整块碎片。

困难规则：

- 完整可辨认的角标：标注；
- 被切断、严重遮挡或无法判断边界：作为 ignore 或负样本，规则必须固定；
- 中央花色、人物图案和普通文字：不标注；
- 同一碎片上出现两个完整角标时：分别标注；
- bbox 必须紧贴角标区域，但保留少量一致边距。

如果后续需要方向分类，方向标签必须与旋转增强同步。禁止直接使用会改变文字方向却不更新标签的增强。

数据验证必须检查：

- 图片可读性、重复图片和近重复帧；
- 缺失标签、空标签和多余标签；
- 类别 ID、坐标范围和 bbox 面积；
- 每个 split 的场景、光照、角度和角标大小分布；
- 负样本比例；
- 最小角标像素尺寸；
- 数据来源与许可证清单是否完整。

### 阶段 F：基线实验

在正式训练前，先完成两个基线：

1. 传统视觉基线：亮度/颜色、连通域或模板匹配定位角标。
2. YOLO 基线：`yolo11n` 单类检测。

目的不是用传统算法替代 YOLO，而是确认 YOLO 确实改善了反光、花色干扰和不同位置下的召回率。

下游评估不能只看 mAP，还必须直接统计：

- 角标是否关联到正确碎片；
- `original/swapped` 判断是否正确；
- 错误选择率；
- `AMBIGUOUS` 率；
- 没有证据时是否错误发送动作。

### 阶段 G：YOLO 训练

推荐初始配置：

```yaml
model: yolo11n.pt
imgsz: 640
epochs: 200
patience: 30
batch: auto
pretrained: true
cache: false
rect: false
```

增强原则：

- 允许较大的旋转范围，因为碎片可任意旋转；
- 使用适度 HSV、曝光、模糊、噪声、透视和缩放；
- 限制会生成不真实文字的水平/垂直镜像；
- 若训练方向标签，所有旋转增强必须同步变换方向真值；
- 训练后期关闭或降低 Mosaic，避免小角标边界失真。

每次训练必须保存：

- `args.yaml`；
- `best.pt` 和 `last.pt`；
- 训练曲线、混淆矩阵和逐类指标；
- test split 推理结果；
- 失败样本清单；
- Git commit、数据集版本、随机种子和环境版本。

停止条件：

- 不以单次最高 mAP 直接定版；
- 若真实 test 的小角标召回或下游二选一准确率不达标，先补困难数据，不盲目增加 epochs；
- 若漏检主要集中在像素过小，应先评估裁剪 ROI 或输入尺寸，而不是降低置信度硬接收。

### 阶段 H：方向与候选判别

普通 YOLO 检测框不提供可靠的有向 `0..360` 度信息。推荐按以下顺序实现：

1. 使用角标中心与最近物理圆角构成局部向量；
2. 在两个候选变换后检查向量是否指向牌面内部；
3. 若仍存在 180 度歧义，增加角标 crop 的轻量方向分类器；
4. 若牌面固定，再对两个候选使用局部模板或 SIFT/RANSAC 参考验证；
5. 若仍无法拉开差距，返回 `AMBIGUOUS`。

不建议第一版直接使用 YOLO OBB 或 Pose，除非普通检测加方向分类在真实测试中失败。原因是 CV181x 的检测模型部署链路最成熟，而额外输出头会增加转换和运行时适配风险。

### 阶段 I：圆弧检测移植

参考上游 `v2.2.0-vision-rounded-card`，只移植几何思想，不照搬黑色背景阈值和固定尺寸。
该仓库目前未发现明确许可证；未取得作者许可前必须参考公开思想独立实现，不能直接复制
上游源码进入交付项目。

建议实现步骤：

1. 扑克分割同时保留实测外轮廓和供模式二使用的恢复多边形；
2. 在轮廓上寻找位于两条长直边之间的 1 至 3 段短弦；
3. 检查两侧长边长度、近似垂直关系和圆弧切深；
4. 延长两侧长边求交点，形成供几何求解使用的虚拟直角；
5. 将实测轮廓和恢复多边形做全局一一关联；
6. 根据完整扑克牌只有 4 个物理圆角的先验做全局筛选；
7. 所有阈值优先用毫米或相对周长表示，再换算到 `0.5 mm/px`。

圆弧模块必须输出：

- 碎片 ID；
- 实测圆弧点或短弦；
- 虚拟直角；
- 圆弧置信度；
- 被拒绝候选及原因。

### 阶段 J：接入现有求解器

建议新增独立模块，而不是把模型逻辑塞进 `task2_white.py`：

```text
solvers/poker_arc_geometry.py
solvers/poker_corner_detector.py
solvers/poker_layout_selector.py
```

接入边界：

- `task2_white.py` 保持共享几何搜索和动作生成；
- `task3_poker.py` 负责扑克分割、圆角信息和调用布局选择器；
- YOLO 模型只在程序启动时加载一次；
- 每轮对 `rectified_rgb` 推理一次并缓存结果；
- 检测框通过点在多边形内、交并比或掩膜覆盖率关联到碎片；
- 用无安全间隙的目标变换进行视觉评分；
- 最终仍使用现有带安全间隙的目标变换生成 `PieceAction`；
- 不修改 UART 字段、顺序、ACK 流程和发送节拍。

同形对识别必须使用多项几何特征：

- 面积；
- 周长；
- 顶点数；
- 归一化边长序列；
- 最小外接矩形长宽比；
- 正方形/长方形判定。

如果没有且只有一对可信同形碎片，直接失败，不猜测。

第一版可在模式二返回的合法布局上交换同形两块的目标变换，从而构造两个候选。只有当实拍回归证明模式二还会选择几何结构不同的错误拓扑时，才考虑扩展模式二暴露多个 finalist。

### 阶段 K：ONNX 与 CV181x INT8 转换

确认 PyTorch 模型通过真实 test 后：

1. 导出固定输入尺寸 ONNX，`dynamic=False`、opset 17；
2. 检查 ONNX 输入、输出节点和 letterbox 预处理；
3. 使用 50 至 200 张真实部署场景图做 INT8 calibration；
4. 使用 `tpu-mlir` 转换到 `cv181x`；
5. 生成与类别顺序、预处理和模型文件一致的 MUD；
6. 分别验证 PyTorch、ONNX 和 INT8 的检测结果；
7. 记录 INT8 前后的置信度、漏检和最终候选判断差异。

产物命名必须带分辨率和版本，例如：

```text
poker_corner_yolo11n_640_v1.pt
poker_corner_yolo11n_640_v1.onnx
poker_corner_yolo11n_640_int8_v1.cvimodel
poker_corner_yolo11n_640_int8_v1.mud
```

禁止覆盖已有模型或转换目录。

### 阶段 L：PC 回归验证

必须建立固定测试集，至少覆盖：

- 同形长方形原位；
- 同形长方形交换；
- 同形正方形原位；
- 同形正方形交换；
- 角标靠近切边但完整；
- 强反光、阴影、轻微失焦和压缩；
- 中央花色被误认为角标的负例；
- 仅检测到一个角标；
- 圆角检测少于或多于 4 个；
- 两候选分数接近并返回 `AMBIGUOUS`；
- 输入碎片顺序的全部 24 种排列；
- 原有纯白模式回归不变。

验收重点：

- 错误选择后发送 UART 的次数必须为 0；
- 证据不足时必须无动作输出；
- 真实 test 的二选一准确率应高于单纯 mAP 指标优先级；
- PyTorch、ONNX 和 INT8 的最终选择结果应基本一致；
- 现有模式二、UI、坐标和串口测试全部通过。

### 阶段 M：MaixCAM Pro 真机验证

在用户确认允许部署后执行：

- 上传 `.mud` 和 `.cvimodel` 到独立模型路径；
- 确认模型加载日志中的类型、输入尺寸和 labels；
- 使用真实相机进行有界运行，不无限占用设备；
- 分别记录 `camera.read`、透视、分割、YOLO、圆弧、模式二和候选选择耗时；
- 验证不同位置、旋转、光照和两种交换状态；
- 检查屏幕中间状态和 MaixVision 日志；
- 最后单独验证 UART 电气链路和一块一 ACK 节拍。

真机报告必须区分：

- PC 图片回放；
- MaixCAM 固定图片回放；
- MaixCAM 真实相机；
- 真实 UART/机械执行。

任何一级通过都不能替代后一级。

## 5. 建议验收指标

以下为第一版建议值，正式开始训练前由用户确认：

| 指标 | 建议门槛 |
| --- | --- |
| 真实 test 角标 Recall | `>= 99%` |
| 角标错误关联到碎片 | `0` |
| `original/swapped` 正确率 | `>= 99.5%` |
| 错误候选通过并发送 UART | `0` |
| 无法判断时正确返回 `AMBIGUOUS` | `100%` |
| INT8 与 PyTorch 最终选择一致率 | `>= 99.5%` |
| 圆弧全局计数 | 合法样本恰好 4 个 |
| 纯白模式回归 | 全部通过且行为不变 |

不要用单一 `mAP50` 作为完成标准。最终安全指标是“是否选对候选，以及不确定时是否拒绝发送”。

## 7. AI 执行纪律

- 先读取代码和文档，再修改；
- 只做最小必要改动，不重写模式二；
- 不覆盖数据集、权重、ONNX、MUD 或 cvimodel；
- 不安装生产依赖前先说明原因；
- 不删除用户图片或历史 fixture；
- 不将公开数据、合成数据或 PC 回放声称为真实设备验证；
- 不降低现有几何硬门限来掩盖模型错误；
- 不因 YOLO 高置信度跳过圆角、几何和候选差值门限；
- 不提交或推送 Git，除非用户明确要求；
- 长时间训练前必须由用户确认数据范围、模型、训练参数和产物策略。
